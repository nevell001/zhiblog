# v1.4.4 (2026-10-04)

本版本全部是 v1.4.3 发布之后合入的工作，主题是**文章评论区的对话体验**：回复归位到所属楼层、顶级评论分页并支持排序，评论计数与审核结果保持一致。

## ✨ 新增与增强

- **楼中楼**：回复按所属楼层折叠挂在顶级评论下（此前回复与顶级评论混在同一页平铺，看不出属于哪个楼层），回复与顶级评论一样可点赞、回复、编辑、删除
- **评论分页与排序**：顶级评论每页 10 条并带分页器，支持「最新 / 最早」切换；回复随楼层一并返回，固定按时间正序
- **计数随写入回传**：评论新增 / 修改 / 删除接口返回该文章已发布评论数（含回复），前台评论数直接采用，不再本地推算或猜测审核结果
- 登录用户重新进入文章时回显本人点赞态（含楼层内回复）；发表新评论后回到第一页，最新排序下立即可见

## 🐛 主要修复

- **分页漂移**：评论排序只按 `create_time`，同一秒的多条评论顺序不定，翻页会重复或漏项；改为 `create_time` + `id` 双重排序（最新 / 最早两个方向都兜底）
- **顶级评论判定**：`parent_id` 建表默认 `0`，而插入顶级评论时省略该列、落库即 `0`，所以「顶级」必须同时覆盖 `NULL` 与 `0`，否则楼层会漏
- **回复可挂到任意父级**：前台回复此前不校验父评论，可挂到其它文章的评论或凭空造楼层；现在要求父评论存在且属于同一篇文章
- **删除后停在空页**：删掉当前页最后一条顶级评论后不会自动回退，页面停在空列表；现在回退到最后一页

## ⚠️ 升级提示

- 未改表结构，无需迁移脚本（`sql/00_init_database.sql` 可幂等重跑）
- 变更同时涉及后端接口（评论查询与写入）与前端产物（文章详情页），前后端镜像都需重建：`docker compose -f docker-compose.prod.yml up -d --build`
